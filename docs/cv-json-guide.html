CV JSON developer guide

cv.example.json and cv_english.example.json are the versioned templates. Copy them to cv.json and cv_english.json before adding personal data; the local files are ignored by Git. Both must satisfy the shared JSON Schema.

Validate before committing

npm run validate:cv
npm run build

The build runs validation first, so invalid content cannot be built. The command reports a file and field path for every problem.

Top-level structure

FieldPurpose
basicsIdentity, contact information, location and social profiles.
workProfessional roles. Use an empty string or null in endDate for the current role.
educationFormal education. Set paused: true for paused studies.
diplomas, courses, certificatesAdditional education and credentials.
skills, languages, hobbiesProfessional profile details.
projectsProjects linked to a work entry or grouped as complementary experience.

Conventions

  • Dates use YYYY-MM-DD.
  • URLs must be complete, for example https://example.com.
  • Project company is required: it must match a work name, or be exactly Freelance or Personal. The latter two appear under Complementary experience in print.
  • Use featuredCourses to order high-impact courses and printLimit to choose how many appear in print. Every featured course must be present in courses.
  • Use null only for optional project url or github; do not remove those fields.

Minimal examples

{
  "work": [{
    "name": "Company", "position": "Developer", "startDate": "2024-01-01",
    "endDate": "", "summary": "Short role summary", "highlights": ["Achievement"]
  }],
  "projects": [{
    "name": "Product", "company": "Company", "isActive": true,
    "description": "What it does", "highlights": ["Key outcome"],
    "url": "https://example.com", "github": null
  }]
}

Guía para desarrolladores del CV JSON

cv.example.json y cv_english.example.json son las plantillas versionadas. Cópialas como cv.json y cv_english.json antes de agregar datos personales; los archivos locales están ignorados por Git. Ambos deben cumplir el esquema JSON compartido.

Valida antes de hacer commit

npm run validate:cv
npm run build

El build ejecuta primero la validación, por lo que no se puede generar una versión con contenido inválido. El comando informa el archivo y la ruta de cada error.

Estructura principal

CampoUso
basicsIdentidad, contacto, ubicación y perfiles sociales.
workExperiencia profesional. Usa una cadena vacía o null en endDate para el empleo actual.
educationEducación formal. Usa paused: true para estudios pausados.
diplomas, courses, certificatesFormación adicional y credenciales.
skills, languages, hobbiesDetalles del perfil profesional.
projectsProyectos enlazados a una experiencia laboral o agrupados como experiencia complementaria.

Convenciones

  • Las fechas usan YYYY-MM-DD.
  • Las URLs deben ser completas, por ejemplo https://example.com.
  • El company de un proyecto es obligatorio: debe coincidir con un name de trabajo, o ser exactamente Freelance o Personal. Los dos últimos se muestran como experiencia complementaria en impresión.
  • Usa featuredCourses para ordenar los cursos de mayor impacto y printLimit para decidir cuántos aparecen en impresión. Todo curso destacado debe estar incluido en courses.
  • Usa null solo para url o github opcionales de proyectos; no elimines esas propiedades.

{
  "work": [{
    "name": "Empresa", "position": "Developer", "startDate": "2024-01-01",

  }],
  "projects": [{
    "name": "Producto", "company": "Empresa", "isActive": true,
    "description": "Qué hace", "highlights": ["Resultado clave"],
    "url": "https://example.com", "github": null
  }]
